# Recast 工具实现 — 任务书

## 1. 任务

本仓库 `nai_casrand` 是 Flutter 写的 NovelAI 批量出图工具。需要新增一个叫 **"Script Recast"** 的功能：把一个文件夹的 `nai_*.json`（用户称之为"剧本"）整套拿来，批量替换其中的"演员（角色）"和"画风（画师串）"，把替换后的逐帧 payload 推送到现有的批量产线自动出图。

完整、可执行、能通过本任务书 §5 全部验收场景。

## 2. 需求与边界 — 真理源头

以下三份文档是真理源头。**所有需求、设计、约束以这三份为准**，本任务书与之冲突时以这三份为准：

1. `docs/plans/2026-05-25-script-recast-user-requirements.md` — 用户视角需求说明书（**最高优先级**）
2. `docs/plans/2026-05-25-script-recast-prd.md` — 实现层 PRD
3. `AGENTS.md` — 仓库工作流约定（Beads 任务追踪等）

**先把这三份完整读完再动手**。不许凭直觉编需求。

用户的真实剧本样本位于宿主机：

- `E:\NAI的脚本群\作品集\vulpisfoglia suzuran 忍冬x铃兰 BBC\`（91 帧，v4 槽位）
- `E:\NAI的脚本群\作品集\Chino\`（base 内嵌）
- `E:\NAI的脚本群\作品集\1战败\`（base 内嵌，角色名含空格）
- `E:\NAI的脚本群\作品集\ある輪廻のトリスビアスの物語\`（混合模式）

如果你的执行环境访问不到宿主机，从每个剧本各抽 5–10 帧拷到测试 fixture 目录使用。

## 3. 现有改动的处理

仓库 working tree 当前有大量未提交改动（来自之前的"Novel Studio 整合"方向，部分偏离了用户真实目的）。

**在写任何新代码之前**，先做一件事：把所有未提交改动逐文件评估"保留 / 改造 / 回滚 / 旁置"，输出分类报告并提交 PR 等用户确认。

分类原则（不是分类方法，方法你自定）：

- **不浪费**：能作为 Recast 地基的改动一律保留
- **不带病**：与 Recast 一等公民地位冲突的、或与本任务书 §4 硬约束冲突的改动，回滚
- **不擅自删**：拿不准的改动一律先保留，让用户决定
- **不偷偷做**：用户确认前不许进入新代码阶段

## 4. 硬约束（需求层面的"绝不许"）

以下是需求边界，不是技术建议。任何 PR 违反以下任一条，**默认不接受**：

1. **不许新建并行的角色卡 / 画师串卡模型**——必须在现有素材库的 `CharacterEntry` / `ArtistChain` 上扩展
2. **不许复制一个新的批量产线**——必须复用现有产线
3. **不许把 Recast 做成 Studio Shell 的子菜单**——它是独立一级入口
4. **不许在 UI 上暴露 NAI 高阶画质微调参数**（sm / cfg_rescale / noise_schedule / dynamic_thresholding / controlnet / legacy_v3_extend / eta / negative_momentum / extra_passthrough_testing 等）——这些从原剧本逐帧继承，连"高级折叠"都不要有
5. **不许默认 reroll seed**——换 cast / 换画风时保留 seed 是核心价值
6. **不许默认落盘新 JSON 文件夹**——Recast 成果直接进产线跑成图片；JSON 导出只是可选副产品
7. **不许把 CasRand 随机任务和 Recast 任务在产线 UI 上混在一起没法区分**
8. **不许用模拟数据写测试**——所有测试必须用真实剧本 fixture
9. **不许动用户原剧本文件**——原文件夹永远只读
10. **不许把"负向 / 质量尾模板库"塞进单字符串字段**——必须能多模板组合、并集去重
11. **不许把"换角色 / 换画风"降级成让用户手写 20 条字符串替换规则**——这是高阶语义对象
12. **不许做"看起来全但点了没用"的占位 UI**

更多细则见 §2 引用的需求文档 §6 和 §7。

## 5. 验收场景

所有以下场景必须能跑通，任何一个失败都不算完成。详细描述见需求文档 §10。

- **A 换演员**：拖剧本进来，选两张新角色卡，按"发送到产线"，91 帧自动出图新角色
- **B 换画风**：同剧本不换角色，换画师串卡，出图画风改变构图保留
- **C 换异质剧本**：四种不同结构剧本（v4 槽位 / base 内嵌 / 混合）全部能正确解析并完成 A 流程
- **D 容错**：人工破坏一帧 JSON，运行不崩溃，该帧标 error，其余帧正常完成
- **E 可重复性**：同一配置跑两次，输出字节级一致（除时间戳）
- **F 可控保留**：复合配置（部分跟随、部分保留、部分覆盖、含帧级覆盖）正确生效
- **G 状态可见性**：Recast 配置页不滚不展开就能看见每一项当前是"保留 / 跟随 / 覆盖"中的哪个；NAI 高阶参数在 UI 上找不到入口
- **H 产线参数极简**：产线设置页参数项数量极简，看不到 NAI 高阶参数
