# 批次随机间隔设计

## 目标

在现有“批次间隔时间（秒）”基础上，新增一个可配置的随机波动区间，让每次 cooldown 的实际等待时间都可以在用户指定范围内浮动。

目标效果：

- 保留现有固定批次间隔配置
- 在设置页新增两个输入框：波动最小值、波动最大值
- 每次进入 cooldown 时，实际等待时间按“基础间隔 + 随机波动”计算

## 当前行为

当前批次等待逻辑是固定秒数：

- 设置项保存在 `Settings.batchIntervalSec`
- 设置页通过 `SettingsPageViewmodel.setBatchIntervalSet()` 编辑
- 生成页在 `GenerationPageViewmodel.setCooldown()` 中直接使用 `Duration(seconds: batchIntervalSec)`

也就是说，当前每次 cooldown 的等待时间完全相同，没有随机性。

## 需求定义

采用“基础间隔 + 波动区间”的设计：

- 保留现有 `批次间隔时间（秒）`
- 新增：
  - `随机波动最小值（秒）`
  - `随机波动最大值（秒）`

每次 cooldown 的实际时间为：

- `actualCooldownSec = batchIntervalSec + randomJitterSec`
- `randomJitterSec` 取值范围为 `[minJitterSec, maxJitterSec]`

例如：

- 基础间隔 = 30
- 最小波动 = 10
- 最大波动 = 40

则每次等待时间都会随机落在 `40 ~ 70` 秒之间。

## 备选方案

### 方案一：基础间隔 + 最小/最大波动（选中）

保留一个基础间隔，再新增两个波动输入框。

优点：

- 与现有设置最兼容
- 用户容易理解
- 默认值设为 0 时可完全退回当前固定行为

缺点：

- 配置项从 1 个变成 3 个

### 方案二：直接改成最小间隔 / 最大间隔

不再保留基础间隔，直接让用户配置最终等待区间。

优点：

- 概念更直接

缺点：

- 会改变已有设置语义
- 与现有 `batch_interval` 配置不兼容

### 方案三：基础间隔 + 单个波动幅度

例如基础间隔 30，波动幅度 15，则随机范围是 30 ~ 45 或 15 ~ 45。

优点：

- 输入框更少

缺点：

- 语义不如最小/最大值清晰
- 无法精确表达用户想要的具体区间

## 选中方案

采用方案一：保留现有基础间隔，新增最小/最大波动输入框。

该方案兼容性最好，也最符合当前已经确认的交互预期。

## 数据模型设计

在 `Settings` 中新增两个整数字段：

- `batchIntervalJitterMinSec`
- `batchIntervalJitterMaxSec`

要求：

- `fromJson()` 提供默认值 `0`
- `toJson()` 写回配置
- 旧配置文件缺少这两个字段时，自动按 `0` 处理

这样老用户升级后，默认行为仍与当前完全一致。

## UI 设计

设置页的批次设置区域保持现有结构，在 `批次间隔时间（秒）` 下新增两个二级输入项：

- `随机波动最小值（秒）`
- `随机波动最大值（秒）`

要求：

- 使用与现有数值设置一致的 `EditableListTile`
- 键盘类型保持数字输入
- 输入非法值时沿用当前策略：解析失败则忽略本次修改

批次设置摘要文案第一版可以先保持不变，不强制把随机区间也塞进 subtitle，避免文字过长。

## 执行逻辑设计

`GenerationPageViewmodel.setCooldown()` 改为：

1. 读取基础间隔 `batchIntervalSec`
2. 读取波动最小值 / 最大值
3. 规范化范围，确保 `min <= max`
4. 在范围内随机得到本次 `randomJitterSec`
5. 计算 `actualCooldownSec = base + jitter`
6. 用这个实际秒数启动 cooldown timer

## 边界与容错规则

### 默认值

- `min = 0`
- `max = 0`

此时行为与当前固定间隔完全一致。

### 用户填反

若用户填写：

- 最小值 40
- 最大值 10

代码中自动按排序后的区间处理，即视为 `[10, 40]`。

不额外弹错误提示，避免设置过程变得烦琐。

### 负数处理

第一版建议在写入 viewmodel 时直接限制为非负数：

- 负数按 `0` 处理

这样可以避免生成负等待时间或复杂解释。

## 文案设计

需要新增中英文文案键，建议为：

- `batch_interval_jitter_min`
- `batch_interval_jitter_max`

对应文案：

- 中文：
  - `随机波动最小值（秒）`
  - `随机波动最大值（秒）`
- 英文：
  - `Minimum random jitter (seconds)`
  - `Maximum random jitter (seconds)`

第一版不修改 `appbar_cooldown` 文案。

## 测试策略

至少覆盖以下内容：

1. `Settings` 能正确序列化 / 反序列化两个新字段
2. 设置页 viewmodel 能正确写入两个新值，并对负数进行非负化处理
3. cooldown 时间计算在 `min = max = 0` 时退化为固定间隔
4. cooldown 时间计算在有波动时，结果始终落在合法区间内
5. 当用户填反最小值和最大值时，系统仍能在排序后的区间内工作

## 风险与兼容性

本次改动兼容旧配置，因为新增字段默认为 `0`。

主要注意点：

- 随机等待时间是每次 cooldown 临时计算，不会持久化本次结果
- AppBar 仍只显示“cooling down”，不显示当前随机秒数
- 若后续用户希望“看到这次具体暂停了多少秒”，可以在下一版再补显示层支持
