## 1. 我是谁，我在做什么

我是一个用 NovelAI 做图像创作的个人用户。我的日常产出不是单张图，而是**一整个"剧本"——按帧排列的、姿势构图连续的多帧 NAI 出图序列**。一个剧本通常 50–100 帧，讲一个完整的故事/场景循环。

我手上已经有：

- 几十个调好的剧本，存放在 `E:\NAI的脚本群\作品集\` 下，每个剧本是一个独立文件夹
- 一套画师串调色记录（`画师串记录.xlsx`、`画师串数据/`、`画师串工作室/`）
- 一些手工/AI 整理工具（`分词器.py`、`提示词工作室.py`、`小工具/` 下的脚本）
- 一些剧本旁边的 `_Py_Reorganized/` 和 `_AI_Reorganized/`，是我之前用脚本/AI 把剧本拆成"场景|角色|其他"结构化提取的成果

我不缺素材，也不缺单帧 prompt 能力。**我缺的是把"剧本"作为一个对象去高效操作的工具。**

## 2. 一个"剧本"在我的文件系统里长什么样

以 `vulpisfoglia suzuran 忍冬x铃兰 BBC` 为例：

```
vulpisfoglia suzuran 忍冬x铃兰 BBC/
├── nai_1.json          ← 一帧的 NAI 出图元数据
├── nai_2.json
├── ... （共 91 个）
├── nai_91.json
└── _Py_Reorganized/    ← 我用脚本把每帧的角色和场景拆出来的整理结果
    ├── _ALL_SUMMARY.txt
    ├── _SUMMARY_CHAR_01.txt   ← 整剧 91 帧里角色 1 的样子
    ├── _SUMMARY_CHAR_02.txt   ← 角色 2
    ├── _SUMMARY_SCENE.txt     ← 场景部分
    └── _RESOLUTIONS.txt
```

每个 `nai_*.json` 里关键的部分：

- `Description` / `Comment.prompt` — 完整的 prompt 字符串
- `Comment.v4_prompt.caption.base_caption` — 场景 / 画师 / 构图 / 质量尾
- `Comment.v4_prompt.caption.char_captions[]` — 角色槽位（每个角色一段 prompt + 一个位置坐标）
- 其他 NAI 参数（seed、steps、scale、sampler、分辨率…）

**剧本之间的写法差异极大**——有的角色全在 `char_captions[]` 槽位里，有的角色直接写在 `base_caption` 文本里，槽位是空数组；画师串的写法也有 `artist:xxx`、`artist_xxx`、裸名等多种，权重语法有 `1.5::xxx::`、`{{xxx}}`、`(xxx:1.2)` 三种以上。

## 3. 我现在的痛点

### 3.1 主要痛点：换演员、换画风是手工活

我经常想做的事情：

> "我这个剧本（91 帧）讲得很好，但我想看同一个故事换两个不同的女主演会怎样" 
>
> "我这个剧本的画风我想换成另一组画师串看看效果"

**目前要做这件事**，我得：

1. 手工开 91 个 JSON
2. 每个文件里找到角色名（`vulpisfoglia_(arknights)`、`suzuran_(arknights)`），手工改成新角色
3. 还要顺便处理角色专属 tag：fox_tail（兽娘尾巴）、spade tattoo（红心纹身）、red collar、nipple rings、small_breasts、tally、body_writing… 新角色不是兽娘怎么办、纹身位置要不要换、奶子大小要不要换
4. 画师串也是同样的手工活，91 个文件里那一长串 `0.8::artist:xxx::, 0.6::artist:yyy::, ...` 都要改
5. 改完了还要确认 91 个文件都没改坏，再丢回 NAI 跑

**这套流程现在就是地狱**。我宁愿不做。

### 3.2 次要痛点：现有 NAI_NEW 项目偏离了我的目的

我看了一下 `NAI_NEW` 仓库目前的方向（Novel Studio 三源整合）：

- 它在做的是"通用 NovelAI 创作工作室"：素材库 / 工作台 / 批量产线 / 画廊
- 它把 CasRand 的"随机抽 prompt 跑量"当成批量产线的核心
- 它把"全局替换"做成生成时的字符串子串替换规则（`PromptReplaceRule`）

**这些都不解决我的核心问题**：

- 我的需求不是"通用创作工作室"，是"剧本 transform 流水线"
- 我的需求不是"随机生成"，是"确定性替换"——剧本骨架完全不变，只是换演员/换画风
- "全局替换"那种字符串规则太底层、太散，我心里想的是"角色 A 整张卡换成角色 X""画师串 A 整组换成画师串 X"这种**高阶语义对象**，不是 20 条 source→target 规则

我担心继续按当前方向整合下去，做出来一个"看起来很全"的工作室，但**我每次还是要为了换演员手动写一堆替换规则**——那等于白做。

## 4. 我希望的工具，一句话说清

> **给我一个工具，让我可以把一个剧本文件夹拖进去，选两张"角色卡"放到对应槽位，选一张"画师串卡"作为新画风，勾选这次替换里哪些东西保留、哪些跟随、哪些覆盖，按"开始"，整个剧本所有帧直接推送到批量产线开始自动出图。**

这是核心循环。其余都是为这个循环服务的辅助能力。

里头的两个关键词：

1. **"勾选哪些保留 / 跟随 / 覆盖"**——不是可选项，是核心循环的一部分。我永远不接受"工具自动帮我决定一切"，我要的是"工具帮我把每一个维度的状态都摊开，让我批量勾选"。详见 §6。
2. **"直接推送到批量产线"**——不是给我输出 JSON 文件夹让我自己再拖回去跑。Recast 配完，按一下"发送到产线"，剩下的事情产线接手。详见 §6.1 和 §6.2。

## 5. 必须满足的能力（按优先级排）

### 5.1 P0 — 没做到就等于没做

1. **以"剧本文件夹"为输入单位**。我拖一个文件夹进去，工具应当识别整套 nai_*.json 是一个剧本，而不是 91 个孤立文件。
2. **以"批量产线"为输出形式**。Recast 配完后按"发送到产线"，整个剧本的 91 帧作为一个执行任务推送给批量产线，产线自动按帧出图。**不需要也不应该给我落盘新的 JSON 文件夹**——成果直接体现为产线里跑完的 91 张图。落盘 JSON 仅作为 P2 可选导出能力存在（见 §5.3）。
3. **替换"角色"是高阶语义操作，不是字符串规则**。我应当能：
   - 给一个角色定义一张"角色卡"：角色锚点 tag + 必带的身体/装饰 tag + 与之冲突的 tag + 可保留的环境 tag
   - 把剧本里"槽位 0 的角色"或"内嵌在 base 里的某个角色锚点"整段换成这张角色卡
   - 一次替换覆盖整个剧本 91 帧
4. **替换"画风/画师串"也是高阶语义操作**。我应当能：
   - 把一组画师 + 各自权重 + 负向调味（`-6::artist:collaboration::` 之类）定义成"画师串卡"
   - 把剧本里整段画师串换掉
   - 一次替换覆盖整个剧本 91 帧
5. **必须能读懂不同作者的剧本**。我已经验证过，至少有 3 种结构：
   - V4 槽位剧本（角色在 `char_captions[]` 里）
   - 内嵌剧本（`char_captions = []`，角色直接在 base_caption 文本里）
   - 混合剧本（部分槽位 + 部分内嵌）
   工具不能假设固定结构，必须用探测 + 投票的方式处理，**任何一种我已有的剧本都不能解析失败**。
6. **必须能容忍写法噪声**：中英文逗号混用、全/半角冒号混用、不同的权重语法（`1.5::xxx::`、`{{xxx}}`、`(xxx:1.2)`）、`artist:xxx` / `artist_xxx` / 裸名画师、负权重 `-6::xxx::`、年份偏置 `year 2024`、错别字（`motion liens`、`face cous`）——全部要被宽容地解析。
7. **绝对不能破坏我已有的剧本文件**。原文件夹只读，所有输出去新文件夹。中间崩了也不能改坏任何原文件。
8. **三态可控的保留/替换策略**。对剧本里**每一类**参数和 prompt 段落，我应当能选择三种状态之一：
   - **保留 (lock)**：原文件里是什么，新文件里就是什么。Recast 不动它。
   - **跟随 (follow)**：默认状态，受 Recast 替换规则（角色卡/画师串卡）的影响。
   - **覆盖 (override)**：我提供一个新值，不论原值是什么、卡里是什么，都用我给的新值。
   
   这个选择必须是**批量级**的：我能在剧本配置页里一次性勾选"整个剧本所有 seed 都保留""所有 sampler 覆盖为 k_dpmpp_2m""所有 negative prompt 跟随替换"。具体可控对象的完整清单见 §6。
9. **三态状态必须显式可见**。任何参数当前是"保留 / 跟随 / 覆盖"中的哪种，必须在 UI 上能一眼看到。**不接受"隐藏默认值"或"工具替你聪明地决定"**。

### 5.2 P1 — 没做到很难受，但可以晚一版本

8. **预览 diff**。开跑前能让我看到首/中/末几帧"原 prompt vs 新 prompt"的高亮差异，确认没出错再开跑。
9. **dry-run 模式**。可以"假装跑一遍"，只产新 JSON 不调 NAI API，让我先肉眼检查 JSON 是否正确。
10. **断点续跑**。91 帧跑到一半中断（崩溃、断网、关电脑），下次能从中断帧继续。
11. **失败帧不阻塞整体**。某一帧解析或调用失败，标记后跳过，其余帧继续；跑完后可以重试失败帧。
12. **seed 默认保留**。换演员/换画风时 seed 不变是 Recast 的核心价值——它让"同一个故事用不同 cast 演一遍"在视觉上具有连续性。要明确把 `seed = 保留` 作为默认值，不允许默认 reroll。
13. **角色卡 / 画师串卡可以从我已有的剧本里"反向提取"**。我不应该被迫从零写角色卡——给我一个剧本，工具应当能扫出它的角色槽位和画师串，让我一键"另存为角色卡 / 另存为画师串卡"。
14. **可保存"保留预设"**。我做过 N 次相似的 Recast，没必要每次重头勾选。一份"保留/跟随/覆盖"配置可"另存为预设"（例：`换演员-保留场景画风` / `换画风-保留cast` / `换画风+换演员`）。下次拖入新剧本时直接选预设，再做小调整即可。预设可导入/导出 JSON。
15. **帧级覆盖**。绝大多数控制在剧本级即可，但允许对个别帧单独覆盖——比如第 50 帧是中场休息的特写，我不想换画师；或者第 80 帧需要单独换 sampler。覆盖的帧在时间线上要有明确标记，方便回看。

### 5.3 P2 — 锦上添花

14. 角色卡之间的"冲突 tag 自动建议"（比如新角色不是兽娘，自动建议删除 `fox_tail`、`paw_pose`）。
15. 画师串总权重归一化建议（避免新画风总权重爆炸）。
16. 复用我已有 `_Py_Reorganized/` / `_AI_Reorganized/` 的成果作为角色卡的种子。
17. 历史 Recast 的 diff 报告导出（Markdown）。
18. 剧本封面、剧本库网格视图。

## 6. 可控对象与参数归属

这一节展开 §5 第 8 条。两个目标：

- 把所有可控对象摊开，让我能逐项设置"保留 / 跟随 / 覆盖"三态；
- 同时明确哪些参数**根本不该出现在 UI 里**——它们从原剧本逐帧继承即可，省得多管。

### 6.1 输出形态：直接进批量产线

Recast 配置完成后，工具行为是：

```
[Recast 配置页]
  └─ 按"发送到产线" ─→  [批量产线]
                          ├─ 任务 1: vulpisfoglia_Recast_娜西妲x芙宁娜
                          │   ├─ 91 帧自动入队
                          │   ├─ 进度可视化
                          │   ├─ 失败可重试
                          │   └─ 输出 = 91 张 PNG（产线管理）
                          └─ ...其他剧本任务
```

**不要做的事**：

- ❌ 不要默认落盘"新 JSON 文件夹"。我已经有 40+ 个剧本文件夹，再多 N 个 "_Recast" 文件夹只会污染我的 `作品集/` 目录。
- ❌ 不要把"发送到产线"做成"先落盘再让用户手动导入产线"——这是两步操作，应该是一步。
- ❌ 不要在 Recast 页内重新发明一套"产线 UI"——直接复用批量产线，少做一份事。

**可选导出（P2）**：偶尔我会想把 Recast 配置成果存档备份，这时允许我从产线任务详情页"导出本任务的 91 个 JSON"，但不是默认行为。

### 6.2 批量产线的瘦身要求

当前批量产线（如果按 Novel Studio PRD 走 CasRand 随机 config 树那一套）参数极多。Recast 工作流要求产线在**作为 Recast 下游消费方时**做大幅简化：

1. **产线设置只暴露通用全局参数**——见 §6.3 的 A、B、C 三档。
2. **剧本/帧特定的参数全部从原剧本逐帧继承**——见 §6.3 的 D、E、F 三档，UI 上根本不出现。
3. **产线接到 Recast 任务时不要求用户再配一次参数**。Recast 配置 + 产线全局设置 = 完整执行参数集，产线直接开跑。
4. **产线对 CasRand 随机模式 和 Recast 确定性模式应有清晰分离**。这两种模式可以共存，但 Recast 任务不允许被随机 config 树污染。

### 6.3 参数归属总清单 ⚠ 待你逐项确认

下面是从 NAI v4.5 JSON 里探测到的全部参数，按归属分成 6 档。每一项标了**我的建议**，⚠ 标记的项我没把握，请你直接告诉我"调到 X 档"。

#### A. 产线全局参数（在产线设置里能改，跨任务通用）

| 参数 | 含义 | 我的建议 |
|---|---|---|
| **模型版本（Source）** | NAI Diffusion V4.5 / V4.6 等 | ✅ A 档（你已明确要） |
| **steps（步数）** | 28 / 32 / 50 等 | ✅ A 档（你已明确要） |
| **sampler（采样器）** | `k_euler_ancestral`、`k_dpmpp_2m` 等 | ⚠ A 档候选——多数场景统一就够，但不同剧本可能想用不同采样器 |
| **scale（CFG Scale）** | 提示词强度，常见 5–8 | ⚠ A 档候选——同上 |

#### B. 执行控制参数（在产线设置里改，与"怎么发请求"有关）

| 参数 | 含义 | 我的建议 |
|---|---|---|
| **NAI API Token / 账号** | 调 NAI API 的认证 | ✅ B 档（必须）|
| **并发数** | 同时跑几张图 | ✅ B 档 |
| **请求间隔** | 两次请求之间等多久（避免被限速）| ✅ B 档 |
| **失败重试次数** | 单帧失败时重试几次 | ✅ B 档 |
| **输出目录** | 出图保存到本地哪个文件夹 | ✅ B 档 |

#### C. 内容模板参数（产线提供默认，剧本可在 Recast 里选择是否覆盖）

| 参数 | 含义 | 我的建议 |
|---|---|---|
| **默认负向提示词模板** | 通用的 `nsfw, lowres, artistic error, ...` | ⚠ C 档——产线提供一份标准负向，剧本默认跟随，可在 Recast 里选"保留原剧本负向" |
| **默认质量尾** | `very aesthetic, masterpiece, no text` | ⚠ C 档——同上 |

#### D. 剧本逐帧继承参数（从原 nai_*.json 读，UI 不出现）

这些是"NAI 高阶画质微调"，你已明确表示不知道它们是什么意思——所以它们**绝对不该出现在 UI 上**。原剧本每帧是什么值，新出图就用什么值：

| 参数 | 含义（仅供日后查阅） |
|---|---|
| `sm`、`sm_dyn` | SMEA 采样修正开关 |
| `cfg_rescale` | CFG 重缩放系数 |
| `noise_schedule` | 噪声调度算法（`karras`/`native` 等）|
| `uncond_scale` | 无条件采样强度 |
| `dynamic_thresholding` 及其 percentile、mimic_scale | 动态色彩阈值 |
| `controlnet_strength`、`controlnet_model` | ControlNet 配置 |
| `legacy_v3_extend` | 兼容旧 V3 模型 |
| `n_samples` | 一次生成几张（一般 1）|
| `negative_momentum` | 负向动量 |
| `eta` | 采样随机性补偿 |
| `extra_passthrough_testing.*` | NAI 官方 A/B 测试字段 |

#### E. 剧本逐帧继承参数（可在 Recast 里选择覆盖）

这些虽然技术上属于 NAI 参数，但**有业务含义**，允许 Recast 配置时统一覆盖：

| 参数 | 含义 | 我的建议 |
|---|---|---|
| **width / height（分辨率）** | 1024×1024 / 1216×832 等 | ⚠ E 档——默认继承原剧本，可在 Recast 里选"全剧统一覆盖为某分辨率"（适合重制为新尺寸）|
| **seed** | 随机种子 | ✅ E 档——默认保留，可改为"按帧 +N 偏移"或"全剧固定"或"reroll"（参见 §6.1 P0 #12）|
| **char_caption.centers (x,y)** | 角色在画面中的坐标 | ⚠ E 档——默认继承，可在 Recast 里"全剧统一覆盖"或"按槽位重置" |
| **use_coords** | 是否启用坐标 | ⚠ E 档——同上 |
| **use_order** | 是否按 char_captions 顺序绑定角色 | ⚠ E 档——同上 |
| **legacy_uc** | 是否走旧式负向模式 | ⚠ 建议放 D 档（隐藏继承），但因为可能影响兼容性，标 ⚠ 让你定 |

#### F. 自动管理字段（用户不需要选）

| 字段 | 工具自动处理方式 |
|---|---|
| `Description` / `Comment.prompt` | 始终基于新 `v4_prompt` 重新生成，无需用户介入 |
| `Generation time` | 每次重置为本次产线运行时间 |
| 文件名 / 帧序 | 沿用原剧本 `nai_N.json` 编号；产线任务以剧本名+替换 cast 命名 |

### 6.4 Prompt 段落类（PromptSegments）

工具需要在解析时把每帧的 prompt 切分成下列段落，并允许我对每一段独立设置三态：

| 段落 | 含义示例 | 我通常想要的默认 | 可选状态 |
|---|---|---|---|
| **角色锚点** | `vulpisfoglia_(arknights)` / `kafuu_chino` | 跟随（被角色卡替换）| 保留 / 跟随 / 覆盖为指定锚点 |
| **角色身份tag** | `fox_tail`、`small_breasts`、`body_writing`、`tally` | 跟随 | 保留 / 跟随 / 覆盖 |
| **角色装饰tag** | `red collar`、`micro_bikini`、`nipple rings`、`white_bikini` | 跟随 | 保留 / 跟随 / 覆盖 |
| **角色状态tag** | `blush`、`tongue out`、`drooling`、`ahegao`、`tears` | 保留 | 保留 / 跟随 / 覆盖 |
| **角色专属纹身/印记** | `1.5::spade tattoo on the stomach::` | 跟随 | 保留 / 跟随 / 覆盖（位置/形状/权重）|
| **场景背景tag** | `love hotel`、`bed`、`public_restroom`、`tile_wall` | 保留 | 保留 / 跟随（如有场景卡）/ 覆盖 |
| **构图视角tag** | `from above`、`bird's_eye_view`、`close up face`、`from side` | 保留 | 保留 / 覆盖 |
| **动作/姿势tag** | `squatting`、`standing sex`、`spread legs`、`grabbing from behind` | 保留 | 保留 / 覆盖 |
| **画师串** | `0.8::artist:terasu_mc::, artist:ratatatat74, ...` | 跟随（被画师串卡替换）| 保留 / 跟随 / 覆盖 |
| **风格偏置** | `year 2024`、`pastel colors`、`HDR`、`flat color` | 跟随（属画师串卡的一部分）| 保留 / 跟随 / 覆盖 |
| **NSFW 调味** | `-2::censored::`、`-3::simple illustration, x-ray::`、`0.8::depth of field::` | 保留 | 保留 / 跟随 / 覆盖 |
| **质量尾** | `very aesthetic, masterpiece, no text` | 保留 | 保留 / 覆盖 |
| **负向 base** | `nsfw, lowres, artistic error, ...` | 保留 | 保留 / 跟随（画师串卡可附带负向）/ 覆盖 |
| **负向 char（按槽位）** | `v4_negative_prompt.caption.char_captions[i]` | 保留 | 保留 / 跟随 / 覆盖 |

> **关键**：上面的"段落分类"由 parser 自动给出，但所有归类都允许我手工调整。比如 parser 把某 tag 误归为"场景"我觉得它该是"动作"，我能在解析视图里直接重新归类，并把它写回该剧本的 `parserOverrides.json`，下次再开同样按我的归类来。

### 6.5 帧级覆盖（FrameOverride）

剧本级配置覆盖整剧 91 帧，但允许"针对某帧"做单独覆盖：

- 在帧时间线右键某一帧 → "为这一帧单独覆盖配置"
- 该帧的 Recast 输出会用其覆盖配置，而不是剧本级配置
- 覆盖了的帧在时间线缩略图上有明显标记（小圆点 / 颜色边框），方便回看与撤销
- 帧级覆盖也可以"批量"——比如"第 50–55 帧全部锁定 sampler 为 X"

### 6.6 保留预设（PreservePresets）

一份完整的"保留 / 跟随 / 覆盖"配置可以另存为预设。设想中我会维护几个常用预设：

| 预设名 | 描述 |
|---|---|
| `换演员-保留画风` | 角色全跟随、画师串和风格偏置保留、场景/构图/参数保留 |
| `换画风-保留cast` | 画师串和风格偏置跟随、角色全保留、场景保留 |
| `换演员+换画风` | 默认状态，角色和画师串都跟随，其余保留 |
| `重制为新分辨率` | 全部保留，仅覆盖 width/height |
| `迁移到新 NAI 模型` | 全部保留，仅覆盖 Source 模型版本 |

每个预设可:
- 选定一份基础剧本后一键应用
- 应用后再做微调（不破坏预设）
- 导出 JSON 分享给别人，或在不同机器间同步

### 6.7 控制台的呈现要求

这部分是 UI 强约束：

- §6.4–§6.5 的所有可控对象**默认全部可见**，不要做"高级设置"折叠把关键控制藏起来
- §6.3 D 档参数（NAI 高阶画质微调）**绝对不出现在 Recast UI 上**，无论"高级"还是"开发者模式"都不应该有入口——因为它们应该 100% 从原剧本继承
- §6.3 A、B 档（产线全局参数）应在**批量产线设置**里管理，不在 Recast 配置页里重复出现
- §6.3 C、E 档（剧本可覆盖参数）才出现在 Recast 配置页，作为三态切换器
- 每一项左侧有三态切换器（lock / follow / override），状态有清晰图标+颜色区分（如：🔒 / ⇄ / ✏️）
- 切换到 override 时立刻展开输入框/下拉，不要让我多点一下"展开"
- 顶部有"一键预设"区，能直接套用已存预设
- 顶部有"批量操作"区：全部保留 / 全部跟随 / 反选 / 按类别批量切换
- 改动过的项有明显视觉差异，能一眼看出"我相对于预设/默认值改了哪些"
- 主行动按钮是**"发送到批量产线"**，不是"保存"或"导出"

## 7. 我明确不要的东西

- ❌ **不要把它做成"通用 NovelAI 工作室"的一个子菜单**。它是独立的纵向工具，不要让我"先进入素材库 → 再进入工作台 → 配置 7 步 → 然后找到 Recast 入口"。Recast 是一级入口。
- ❌ **不要让我手工写 20 条 source→target 字符串规则去模拟"换角色"**。这是把高阶意图降级成低阶操作，等于没做。
- ❌ **不要随机化我的剧本**。Recast 是确定性 transform，不是抽奖。CasRand 的随机 config 树跟这个工具是完全两码事，不要混进来。
- ❌ **不要碰我的原文件**。原剧本文件夹永远只读。
- ❌ **不要试图"理解我的故事"或者"自动续写剧本"**。我不需要 LLM 帮我编剧。我只需要确定性地换 cast 和换画风。
- ❌ **不要因为某一帧解析不出来就拒绝整个剧本**。给我容错，不要给我洁癖。
- ❌ **不要默认 reroll seed**。换 cast/画风时保留 seed 是核心价值，默认值必须是"保留"。
- ❌ **不要在 MVP 阶段就强依赖素材库/画廊**。角色卡和画师串卡 MVP 阶段用本地 JSON 文件即可，不要等整个 Studio 起来才能用。
- ❌ **不要做黑箱默认值**。绝不允许"工具替你聪明地决定"哪些参数保留、哪些不保留。每一项的当前状态都必须摊在我面前可见可改。
- ❌ **不要把可控项藏在"高级设置"里**。§6 里列的所有对象都是日常控制对象，不是高阶玩家专属。
- ❌ **不要在我没开启帧级覆盖时偷偷给某一帧"特殊处理"**。剧本级配置就该 91 帧整齐应用，反常处理必须由我显式标记。
- ❌ **不要默认落盘新的 JSON 文件夹**。我的 `作品集/` 目录已经够乱，Recast 的成果直接进批量产线跑成图片即可。JSON 导出只在 P2 作为可选能力。
- ❌ **不要让我在产线里再配一次参数**。Recast 配置 + 产线全局设置 = 完整执行参数集，我按"发送到产线"那一下就该是最后一次确认。
- ❌ **不要把 NAI 高阶画质微调（sm / cfg_rescale / noise_schedule / dynamic_thresholding / controlnet 等）以任何形式暴露在 Recast UI 上**。这些从原剧本逐帧继承，连"高级设置"折叠都不要给我看。

## 10. 怎么判断这工具做得好不好

把以下场景跑一遍，全过就算合格：

### 场景 A：换演员

1. 拖入 `vulpisfoglia suzuran 忍冬x铃兰 BBC/` 文件夹
2. 工具识别为 V4 槽位剧本，91 帧，2 个角色槽
3. 我把槽位 0（忍冬）映射到我手里另一张角色卡 X，槽位 1（铃兰）映射到角色卡 Y
4. 预览首/中/末三帧 diff，所有帧的角色 tag 已替换，场景 tag 不动，seed 不变
5. 按"发送到批量产线"
6. **产线里立刻出现一个名为 `vulpisfoglia_Recast_X×Y` 的任务，91 帧入队**
7. 产线按全局设置（模型 / 步数 / 并发 / Token）自动开跑，进度可视
8. 跑完得到 91 张新角色的 PNG，原 JSON 文件夹完全没动

### 场景 B：换画风

1. 同上剧本，角色不换
2. 选一张新的"画师串卡"
3. 91 帧的 base_caption 中画师串段落整段被替换；负向调味也跟着替换；其余不动
4. 按"发送到批量产线"
5. 产线开跑，画风明显改变，构图姿势保留

### 场景 C：换异质剧本

1. 依次拖入 `Chino/`、`1战败/`、`ある輪廻のトリスビアスの物語/` 三个写法完全不同的剧本
2. 工具分别识别为 `base_inline` / `base_inline` / `v4_partial`，全帧零失败
3. 每个剧本都能正确指认出"角色"和"画师串"
4. 都能完成场景 A 的换演员流程，三个剧本各自作为独立产线任务跑完

### 场景 D：容错

1. 把 `nai_50.json` 主动改坏（删一个字段）
2. 跑 Recast，第 50 帧标记 error，其余 90 帧正常完成
3. 工具不崩溃，diff 报告完整

### 场景 E：可重复性

1. 同一个 Recast 配置跑两次
2. 两次输出的 91 个 JSON 字节级一致（除了时间戳）

### 场景 F：可控保留

1. 同一剧本（vulpisfoglia 91 帧）
2. 配置如下：
   - 角色全跟随（用两张新角色卡替换）
   - 画师串保留（不换画风）
   - 分辨率覆盖为 `1216×832`
   - seed 保留
   - 产线全局设置里步数改为 32
   - 第 50 帧帧级覆盖：画师串改为另一张卡
3. 按"发送到产线"前预览 diff，逐帧检查：
   - 90 帧的画师串与原文件完全一致（保留生效）
   - 第 50 帧画师串与帧级覆盖一致
   - 91 帧的分辨率全部是 `1216×832`
   - 91 帧的 seed 与原文件一致
   - 91 帧的角色 tag 已替换为新角色卡内容
   - NAI 高阶参数（sm/cfg_rescale/noise_schedule/...）全部从原剧本逐帧继承
4. 进产线，91 帧入队，每帧用 `steps=32` 跑
5. 把这次配置另存为预设 `换演员-高分辨率重制`，删除当前配置后重新加载预设，配置完全还原

### 场景 G：状态可见性

1. 打开任意一个 Recast 配置页
2. 不滚动、不展开任何"高级"折叠
3. 我应当能直接看到 §6.4–§6.5 中**每一项**的当前状态（保留 / 跟随 / 覆盖）
4. §6.3 D 档参数（NAI 高阶画质微调）**不应该出现在页面上**——无论高级折叠还是开发者模式
5. 改动过的项有明显视觉差异（颜色/图标）
6. 如果工具有任何"默认行为"是我看不见的，不合格

### 场景 H：产线参数极简

1. 进入批量产线设置页
2. 我看到的参数项不超过 §6.3 A、B 档总和（步数 / 模型 / 采样器? / CFG? / Token / 并发 / 间隔 / 重试 / 输出目录）
3. 看不到任何 §6.3 D 档参数（sm / cfg_rescale / noise_schedule / ...）
4. 把"发送到产线"按钮按下后，产线**不弹任何二次配置弹窗**，直接开跑

## 11. 总结

我要的不是一个"什么都能做"的创作工作室，**我要的是一个把"剧本 transform"这件事做到极致简单的纵向工具**。

如果有一天我能拖个文件夹、选两张卡、按一下按钮，然后去喝杯水回来发现新剧本已经跑完——那就对了。

如果我还需要打开 91 个 JSON 手动改东西，或者需要写 20 条字符串规则去模拟换角色——那不管外面包了多漂亮的"Studio"壳，都是失败的。
