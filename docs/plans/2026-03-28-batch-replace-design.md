# 批量创建全局替换规则设计

## 目标

在“全局替换”面板中新增一个批量规则输入框，允许用户直接粘贴类似 `pink dress, white jacket, short jacket` 的提示词列表，并自动批量创建多条现有的 `PromptReplaceRule` 规则。创建完成后，用户仍可继续使用现有单条规则卡片编辑 `source`、`target`、启用状态和顺序。

## 背景

当前项目已经具备完整的全局替换能力：

- `PromptReplaceRule` 模型使用 `source`、`target`、`enabled` 表达规则
- 规则在 `GeneratePayloadUseCase` 中按列表顺序执行
- `target` 允许为空，表示删除命中的文本
- UI 已提供单条规则的新增、复制、删除、排序和编辑能力

现有缺口仅在于规则录入效率。对于用户已有的一串提示词，逐条点击“添加规则”再粘贴会非常低效。

## 备选方案

### 方案一：面板顶部常驻批量输入区（选中）

在替换规则面板顶部新增多行输入框和“批量创建规则”按钮。用户粘贴后，系统按分隔符拆分为多条规则并追加到现有列表。

优点：

- 交互直接，符合用户“新增一个批量规则输入框”的预期
- 与当前面板的信息架构一致，创建后即可继续精细编辑
- 不改变已有单条规则流程，风险低

缺点：

- 面板顶部会增加一些垂直空间占用

### 方案二：按钮 + 弹窗批量导入

在面板顶部仅保留一个“批量添加”按钮，点击后打开对话框输入批量内容并确认导入。

优点：

- 默认界面更简洁

缺点：

- 多一步操作，不如常驻输入高频
- 对“快速粘贴即创建”的场景不够顺手

### 方案三：复用单条 source 输入，自动展开

当用户在单条规则的 `source` 中输入逗号列表时，自动将其拆成多条规则。

优点：

- 表面改动最小

缺点：

- 行为隐式，容易让用户困惑
- 会把“编辑单条规则”和“批量建规则”混在一起，破坏现有心智模型

## 选中方案

采用方案一：在 `PromptReplaceRulesEditor` 顶部新增常驻批量输入区，并把解析、去空和批量创建逻辑放到 `PromptTabViewmodel` 中。

## 交互设计

### 面板结构

在 `lib/ui/prompt_tab/widgets/prompt_replace_rules_editor.dart` 中保留现有标题、统计信息和“添加规则”按钮，并在提示文案下方插入一个批量创建区域。

批量创建区域包含：

- 一个多行文本输入框，用于粘贴词条列表
- 一个“批量创建规则”按钮
- 一段简短说明，明确支持 `,`、`，` 和换行分隔

### 用户流程

1. 用户进入“全局替换”面板
2. 在批量输入框中粘贴 `pink dress, white jacket, short jacket`
3. 点击“批量创建规则”
4. 系统将输入拆分成三条规则并追加到现有规则列表尾部
5. 每条新规则默认：
   - `source` = 拆分出的词条
   - `target` = `''`
   - `enabled` = `true`
6. 用户可在现有规则卡片中继续把其中任意规则改成别的目标文本，而不是只能做删除

## 解析规则

批量输入按以下规则解析：

- 支持英文逗号 `,`
- 支持中文逗号 `，`
- 支持换行分隔
- 每个分段会做首尾空白裁剪
- 空分段会被忽略
- 保留用户输入顺序
- 不自动去重

不去重的原因是避免系统偷偷改动用户输入。若用户确实需要重复规则或后续人工合并，应由用户自己决定。

## 数据流与职责划分

### ViewModel

在 `lib/ui/prompt_tab/view_models/prompt_tab_viewmodel.dart` 中新增：

- 批量输入的临时字符串状态
- 更新批量输入内容的方法
- 解析批量输入的方法
- 根据解析结果追加多条 `PromptReplaceRule` 的方法
- 创建成功后清空批量输入的方法

解析逻辑放在 ViewModel 中而不是 Widget 中，原因是：

- 更容易单元测试
- UI 只负责展示和触发动作
- 后续若要给别的入口复用同一解析逻辑，也不需要复制代码

### Widget

`PromptReplaceRulesEditor` 负责：

- 展示批量输入框和说明文案
- 读取 ViewModel 当前输入状态
- 调用 ViewModel 执行批量创建
- 在输入为空时禁用批量创建按钮，避免空操作

### Use Case

`lib/data/use_cases/generate_payload_use_case.dart` 不需要修改。批量功能只是更高效地创建现有规则，不改变运行时替换语义。

## 错误处理与边界

- 输入为空或只有分隔符时：不创建规则
- 连续多个逗号或空行：自动忽略空项
- 词条前后有空格、Tab 或全角空白：创建前裁剪
- 已有规则存在时：新规则直接追加到尾部，不覆盖旧规则
- 新建后仍可手动调整 `target`、开关、顺序和删除

## 测试策略

### ViewModel 测试

在 `test/ui/prompt_tab/prompt_tab_viewmodel_test.dart` 增加测试，覆盖：

- 英文逗号拆分
- 中英文混合逗号拆分
- 换行拆分
- 去除首尾空白
- 跳过空项
- 默认 `target` 为空
- 默认 `enabled` 为 `true`
- 创建后规则顺序与输入顺序一致
- 创建后清空批量输入

### Widget 测试

在 `test/ui/prompt_tab/prompt_tab_dashboard_widget_test.dart` 增加或扩展测试，覆盖：

- 面板中能看到批量输入区
- 输入一串批量内容后点击按钮，可生成多条规则
- 创建后规则卡片可见

### L10n 测试

更新 `assets/l10n/zh-CN.json` 与 `assets/l10n/en.json`，并同步维护 `test/l10n/prompt_replace_l10n_keys_test.dart` 中的 key 列表。

## 非目标

本次不做以下扩展：

- 不支持在一行内直接定义 `source -> target` 成对导入
- 不新增批量去重、合并或覆盖策略
- 不修改替换引擎的匹配规则
- 不自动推断用户想替换成什么目标文本

## 实现结论

该需求可以在不改变现有替换模型和执行逻辑的前提下实现，改动范围集中在替换规则编辑器、对应 ViewModel 和测试，风险较低，且能显著提升批量录入效率。
